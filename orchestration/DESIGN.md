# 轻量编排的设计摘要

本页描述编排模块的职责、组合方式与边界。

目标是帮助不同岗位记录、检索、交流和接续工作。程序负责可靠的机械操作，参与者结合证据作业务判断。没有固定岗位顺序，也不要求每项工作形成自动闭环。

| 能力 | 用途 |
| --- | --- |
| [Queue](QUEUE_TOOLS.md) | 发布、读取、原子领取、简短回复；不记录完成、正式判断或验收 |
| [Board](BOARD_TOOLS.md) | 普通交流与关联回复；明确请求、答案和真实人指令 |
| [IM / Inbox](IM_TOOLS.md) | 独立交材料、检索、展开来源和规范入账；失败与不完整结果也可保存 |
| [Listener / Python](PYTHON_TRIGGER.md) | 只读发现；用户自己的可信普通Python脚本组合条件并选择激活 |
| [Host](HOST_TOOLS.md) | 有限HTTP接纳、来源与权限核验、领取和前台进程运行保护 |
| MCP | 包装已有功能，处理默认值、内部动作身份、技术重试和有限返回 |

Queue、Board、IM不依赖触发器或Host才能使用。Inbox不要求先有Queue任务。同一会话可以多次保存，在已有权限内检索或向其他Issue贡献；当前焦点只作默认目标，不授予权限。

新贡献使用新动作身份；同一操作的响应丢失沿原目标、正文、请求和journal恢复。岗位不需要创建、追加、封存成果集合。一个未知动作不普遍阻断其他合法贡献，未知进程也不能被假装释放。

脚本可在主机A通过HTTP监听B，并请求C的Host。服务各管自己的库，编排只经公开HTTP访问IM，不读取IM数据库或凭据文件。Host状态只覆盖自身；多来源条件是观察，不保证跨服务原子性。JSON只保存静态连接，不是另一个策略引擎。

领取不证明启动或完成。Host保护原接纳、领取与单次前台启动；已知busy不是接纳，unknown恢复原请求。业务完成依据IM材料和参与者判断追溯；没有自动退领、重派、全局空闲证明或责任结算。

工具的实际权限仍由服务和宿主绑定，profile名、正文和可见工具不能扩权。认证由可信宿主注入；不要写入提示词、Git或报告。

Host 面向前台会话，不接管任意脱离父进程的后台作业。

具体使用见[入口](README.md)与[岗位用法](ROLE_USAGE.md)。这些是按需能力，不是每轮必须执行的步骤。
