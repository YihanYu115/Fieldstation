# 统一管理语义：推翻、必要依赖与结论材料包

本文说明当前 scoped-v2 证据资格、关系与结论材料投影的计算契约。参与者负责判断证据内容和声明关系；系统按规则计算，不判断科学真伪。

## 1. 唯一事实源与四项区分

权威事实是版本化 Evidence、Scope 内关系、结论采用引用、冻结快照和操作历史。参与者判断内容意义；内核确定性维护投影。编排与 MCP 只能调用公开 HTTP，不另建管理账本或推理引擎。

必须区分：

1. **来源与必要前提**：分析读取过 A，不一定以 A 的正确性为必要前提。
2. **不可用与命题为假**：依据失效会使论证不可用，不自动证明相反命题。
3. **有效与被采用**：C 的仪器故障记录可以有效，但新结论采用 D 时不一定需要它。
4. **完整账本与默认材料包**：历史永久可追溯，不意味着每次把全部历史送给 Agent。

不新增人工维护的 include/exclude、已处理、过时、已恢复、默认隐藏等标签。资格、原因、默认展示位置、变化提示均由以下规则计算；计算结果可以缓存，但不能变成可独立编辑的第二事实源。

## 2. 现有关系与对象的精确定义

仅对新规则身份下的 scoped Evidence 关系规定下表含义，不直接改写其他领域同名关系或旧规则解释。

| 声明 | 精确含义 | 自动效果 |
| --- | --- | --- |
| `B derived_from A` | A 是 B 的生成/分析来源 | 保留出处，不单独要求 A 的正确性，也不产生推翻 |
| `B depends_on A` | B 的这条论证要作为有效依据，必须依赖 A 当前有效且版本匹配 | A 不可用则 B 不可用；A 未决则 B 不能仅凭此成为可用 |
| `C refutes A` | C 对 A 构成明确反驳 | 只有 C 可用时，确定排除 A |
| `C challenges A` | 对 A 提出尚非明确推翻的争议 | 相关争议可发现，不直接判定 A 不可用 |
| `B supports A` | B 对 A 给出支持意见 | 不自动取消反驳、不计票、不自动成为必要前提 |
| 其余关系 | 复现、修订、背景、重复等原有业务说明 | 不静默升级为必要依赖或推翻 |
| Conclusion.`evidence_refs` | 作者明确采用的直接依据根 R | 决定当前结论的依据闭包，不等于所有 Issue 附属材料 |

`impact_policy=hard/soft/informational` 保留作为维护传播强度，不能决定逻辑真假、必要性、审查人数，尤其不能把所有 hard 关系当作 depends_on。当前代码把 derived_from 与 depends_on 都用于发现闭包；新语义必须分开来源导航与必要依据闭包。

仪器例子应表达为 `B derived_from A`，并声明 `B depends_on A`；只记录 derived_from 无法让软件知道 B 是普通分析，还是“发现 A 不可靠”的诊断。C 可以来源于 A 的仪器日志，但不必依赖 A 的测量有效性，不能因此把 C 错建成 depends_on A。

多个 depends_on 一律是 AND：全部必要。两条独立论证 B1/B2 分成两个可独立管理的 Evidence；作者可以采用其中一条。首版不新增 OR 标签、不自动寻找最小支持集、不因一条失败就自动替作者切到另一条。采用多项依据意味着这些引用都属于该结论保存的依据，任一有关变化均需重新比较。

## 3. 快照、资格图与输入完整性

固定同一 IM 账本、有限不可变快照 X、新规则身份。Issue 是发现和采用根的组织位置；节点是有精确版本绑定的论证/观察单元，关系也固定身份与版本。关系的 `scope_issue_id` 记录声明/管理位置，不截断同一账本内从采用根出发的资格闭包。独立 IM 账本仍互不查询。

记：

- `Att(x)`：所有结构有效的 `y refutes x` 的来源 y。
- `Req(x)`：x 显式声明的必要前提，方向为 `x depends_on p`。
- `base(x)∈{T,F,?}`：由领域生命周期和绑定核验计算的基础可使用性；不是新增人工标签。

正常、完整可核验的当前材料 base=T；明确不允许作为当前依据使用的材料 base=F；已知必要绑定过期等需要重新判断的情况 base=?。实际含义由领域校验映射，不能让业务 Agent 自填。

活动必要依赖发生端点版本失配时，必须保留“有一个必要前提尚未满足”的义务，可将对应依赖端口视为 ?，不能简单删边后让 B 变成无前提的 IN。修订/移除必要依赖是一项带理由、身份和版本检查的显式业务修改；不能自动以修复系统为名替用户移除。内容版本与必要依赖声明须保持原子一致。

失配 refutes 不能攻击新版本，给出失配诊断并停止该旧边的作用，不自动 rebind。关系撤回是撤回声明，与系统算出其来源暂不可用是两回事；后者不应修改关系的 active 历史。

缺引用、无权读取必要输入、快照读取失败、预算超限属于计算不完整，必须失败关闭或返回明确不可认证的诊断，不得将缺失输入当作空集合得出“没有反例”。正常图中的未决与系统故障分开报告。

## 4. 统一的三值最小信息不动点

I 表示可用，O 表示不可用，Q 表示未决。O 的原因可以是直接被反驳，也可以是必要依据失效，不等价于命题为假。

从 `I₀=∅, O₀=∅` 开始同步迭代：

```text
Iₖ₊₁ = Iₖ ∪ {x | base(x)=T ∧ Req(x)⊆Iₖ ∧ Att(x)⊆Oₖ}
Oₖ₊₁ = Oₖ ∪ {x | base(x)=F ∨ Req(x)∩Oₖ≠∅ ∨ Att(x)∩Iₖ≠∅}
Q = V \ (I ∪ O)             # 稳定后
```

等价地，在三值逻辑中定义：

```text
usable(x) = base(x) AND (AND usable(p), p∈Req(x))
                      AND (AND NOT usable(a), a∈Att(x))
```

空 AND 为 T；NOT ?=?；F AND 任意=F；T AND ?=?。从全部未知开始求最小信息不动点，不在多个自洽解释间任意选赢家。必要性和反驳共同求解，不能先固定全部反驳资格再另跑依赖传播。

### 性质与证明边界

在信息偏序 `?≤T, ?≤F` 下，该算子单调；有限图从全部未知开始只会把未知确定为 T 或 F，不会在同一快照内反复改口。每个有进展的轮次至少确定一个节点，最多 |V| 次有进展轮次即终止。等价的 I/O 迭代保持不相交；结果是唯一的最小信息不动点，其他自洽但无根据的猜测不被采用。

故结果不依赖输入顺序、节点名字和历史遍历顺序。依赖环不能自证有效；反驳环也不能任意选胜者。外部信息能使环中部分或全部节点确定，不将整个 SCC 永久标未决。

这保证固定快照下的确定性，不保证新增证据永远不改变结果。删除/恢复边后应对新快照重新求解；若实现增量算法，必须与完整求解等价，不沿用失去根据的旧状态。本文不证明所有业务操作可逆。

## 5. 解释规则：计算原因，不维护原因标签

对 O 节点返回实际的原因集合：基础不可用、来自 IN 的直接反驳、来自 O 的必要前提。原因可并存，不应二选一丢掉信息。对 Q 返回未满足的必要绑定、未决前提/反驳者及相关环入口。

确定状态有求解轮次和较早成立的原因，可生成有限解释证书。解释展开按节点/关系版本去重并有界分页，不枚举指数数量的路径；环按明确循环引用展示。原因是服务端派生输出，不写入独立可编辑的“失效/历史”标签。

## 6. 三种材料投影和当前依据闭包

### 6.1 声明依据闭包 B(R) 与有效支持正文 S(R)

作者为某个结论版本指定 R=`evidence_refs`。定义：

```text
B(R) = 最小 S，使 R⊆S 且 (x∈S 且 x depends_on p) ⇒ p∈S
```

这是当前结论声明的必要依据，不是所有候选材料，也不自动沿 supports、derived_from 或 refutes 扩成全文包。进一步定义 `R_valid=R∩I`，有效支持正文 `S(R)=B(R_valid)`。失败根的前提即使单独仍有效，也不能因此冒充独立支撑结论的根。失效或未决根 `R\I` 进入当前缺口摘要，详情按需展开，不将其整条链放入有效支持正文。

保存新的可靠依据时，R 及其必要闭包须为 IN；保存后新事实可使部分根失效，读取时按上述分区展示并报告 needs_update。记录未决发现可用普通贡献，不伪造支持来取得通过。旧冻结包不随当前资格变化而修改。

### 6.2 资格计算与相关争议 P(R)

从 B(R) 出发，递归收集必要前提和所有 refutes 来源，直至闭包，得到资格计算区域 V_R。附加指向该区域的活动 challenges 及其可解释的来源/资格信息，形成相关争议投影。反驳来源的反驳也必须纳入，不能停在一层。

有效支持正文只展示 S(R)；当前有关反驳/争议和依据失效原因另给有界摘要与展开入口。资格计算仍从声明闭包 B(R) 出发，不能因根暂时失效就停止检测其恢复。为确认正文资格而读取的内部计算图不全部塞进模型正文。来源 derived_from 提供追溯链接，默认不把历史来源正文加入依据闭包。

如果一个反例针对结论而非选定数据，必须指向代表该结论论证/可检验主张的 Evidence，纳入相关争议图。首版不从结论自由文本推断反驳目标；结论文本中未登记的额外主张不在自动完整性保证内。不能以只选 D 的方式屏蔽已经明确指向所采用论证的反例。

### 6.3 变化处理包与历史

结论保存的冻结快照是比较基线。当前依据/争议投影与基线不匹配时，生成有界差异及因果解释，指向发生变化的对象版本。切换到新结论与新 R 后，以其新快照为默认基线；旧差异保留在旧结论历史中，不永久复制到新默认包。

未采用的其他有效材料进入可查询的发现目录，不自动进入依据正文，也不自动使当前结论 needs_update。新相关攻击/依赖不能因之前不在投影中而漏掉：订阅可保守覆盖 Scope 事件，事件到来后重算当前相关投影，只有相关语义变化才改变 currentness。

没有当前结论或尚未指定 R 时，只提供有界发现目录及显式工作材料选择；系统不得自行把“全部有效材料”当作当前结论依据。

### 6.4 当前状态充分性与历史路径无关

当前材料投影只依赖当前权威状态 X、当前结论版本声明的 R 和规则身份；R 不是所有历史结论引用的并集。X 必须包含精确证据绑定、当前有效关系及未满足的必要绑定义务，不能只保留 IN 材料。两个操作历史若形成相同的这些输入，当前支持正文、资格和缺口投影必须相同；日志顺序、前会话聊天和旧缓存不能参与裁决。审计事件及操作回执本身可以不同。

变化摘要另显式依赖当前结论保存的冻结基线 X₀；该基线是当前可读的持久状态，不是临时从聊天或操作历史重建的记忆。比较相同当前状态的变化摘要时也须固定相同基线。历史审计与旧包复现是独立查询，不将其内容并入默认当前包。

D 出现但尚未被当前结论采用时，D 只进入发现目录，当前根仍是 B。C 已使 A/B 不可用时，有效支持正文为空，默认给出“当前采用的 B 因 A 的仪器故障失去依据”的短摘要与 ABC 展开引用。只有新版结论明确改用独立 D 后，ABC 才退出默认相关诊断。上述步骤全由当前状态计算，无需智能整理员隐藏历史。

## 7. ABC→D 场景的完整规则

1. 旧结论 K1 采用 B：`R1={B}`，B depends_on A，故正文 `{B,A}`。
2. C 记录 A 实验的仪器故障，C refutes A：C 为 IN，A 为 O/direct_refutation，B 为 O/necessary_basis_failed。K1 进入 needs_update，变化摘要解释 C→A→B，原冻结包不变。
3. 作者基于独立 D 形成 K2，明确 `R2={D}`。若 D 不依赖 ABC 且 ABC 不反驳 D/所采用论证，正文为 `{D}`，ABC 不出现在默认相关争议和变化摘要中，历史仍可查。
4. 后续仅修改 ABC 的无关关系，不应使 K2 失效。若新增 C refutes D，则自动重新纳入相关投影并影响 K2，不能被“已进入历史”屏蔽。
5. 若 E 有效推翻 C，A 和 B 可恢复资格，但系统不自动把 K2 切回 K1，也不强行把 ABC 再加入 D 的正文。是否再次采用 B 由新的内容判断决定。

这实现“保留所有历史、按当前结论只展示必要材料”，不需要智能整理员反复移动或隐藏条目。

## 8. 版本、currentness 与原子交接

定义结论比较投影 `K_R(X)`：新规则身份、结论目标、R、B(R) 的绑定、决定其资格的必要/反驳子图和状态、相关争议的版本化摘要，以及已有需保留的精确上游绑定。序列化排序规范化。无关 Scope 内容、展示页码/预算和当前结论指向自身的 head 不属于这个依据指纹。

保存快照 X₀ 后，局部失配由 `K_R(X) != K_R(X₀)` 或投影不可完整计算产生。跨 Issue 传播仍复用 `Dirty=Reach_G(L)`。Scope 广泛订阅只负责发现可能影响，不能把每个 Scope 写入都直接等同结论失配。

禁止退化为只 hash 正文 ID：未展示的攻击链变化也能改变依据资格。允许暂时保守地对相关投影中的变化触发复查，但不能因为 D 无关的 ABC 历史更新永久重启处理。

材料冻结请求必须显式区分 discovery 与带 R 的依据冻结；保存结论的 evidence_refs 必须与冻结 descriptor 的 R 一致，不能只检查它是大包的子集。原子提交中核验包/视图/Issue/规则/版本仍匹配，然后保存新结论、回执和 head。改用 D 时不能沿用为 ABC 冻结的比较基线。

freeze_id、action_id、CAS、幂等、权限和历史机制复用。新动作准备不做领域写入；重复意图不改变已经保存的结论 head。旧包按旧规则身份读取，新的规则采用 `context-currentness/scoped-v2`，不在 scoped-v1 名下偷换语义。

## 9. 规则示例与不变量

| ID | 情形 | 必须结果 |
| --- | --- | --- |
| U01 | C→B→A 纯推翻链 | A/C IN，B O；长链同一算法 |
| U02 | 多独立反例，仅一条被击败 | 其余 IN 反例继续排除目标 |
| U03 | 反驳环、奇环、自环 | 未决且终止；外部有效反例可打破环 |
| U04 | B 必须依赖 A，C refutes A | A/B 不可用，B 原因是依据失效 |
| U05 | U04 中 B refutes D | B 不再排除 D |
| U06 | U04 再加 E refutes C | A/B 恢复，不覆盖后来的结论选择 |
| U07 | B 依赖 A1、A2，A1 失效 | AND 前提不满足，B 不可用 |
| U08 | B 仅 derived_from A；A 失效 | 不凭来源关系直接使 B 不可用 |
| U09 | A/B 必要依赖循环；混合自我论证环 | 不能自证 IN；保守未决 |
| U10 | 必要前提绑定过期 | 不能靠删掉失配边把消费者升为 IN |
| U11 | ABC→D、ABC 后续变化、新攻击指向 D | 默认正文仅 D；无关更新不失效，新攻击必可发现 |
| U12 | 重排/重复同事实/撤回再恢复/无关账本或不在采用根相关闭包内的材料 | 结果确定、恢复自身效果；账本边界与根相关闭包外的材料隔离，组织 Issue 位置不隔离同账本资格 |
| U13 | 大图预算耗尽/缺引用/无权限 | 不生成伪完整包；旧有效快照不被覆盖 |
| U14 | HTTP 与 MCP 原子提交/重放/旧 freeze_id | 保持权限、CAS、幂等、原子性，旧快照不变 |
| U15 | 不同操作历史到达相同当前语义状态、R、规则与冻结基线 | 支持正文、资格、缺口及变化投影相同；审计日志可不同 |
| U16 | C 推翻 A，B 依赖 A；D 未出现或已出现但未采用 | 支持正文为空；只有当前失效根的有界缺口摘要与展开入口，不倾倒 ABC 全文或所有历史链 |
| U17 | 某根失效但其部分前提仍有效 | 前提不得独立冒充结论支持；另有有效采用根时只展示该根及必要闭包 |

## 10. 明确不做

不推断自然语言真假，不自动选择最优结论，不按支持票数裁决；不自动把 derived_from 改成必要依赖；不实现任意 AND/OR 公式或自动论证搜索；不新增人工状态标签、自动审核岗位或通用代理。

实现职责见[当前架构](WORKFLOW_ARCHITECTURE.md)，变更按[参与开发](../CONTRIBUTING.md)验证。
