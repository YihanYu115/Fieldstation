# Evidence 与当前依据

Evidence 是可独立追溯、质疑、替换和复用的小贡献，可以是观测、计算、解释、理论推导、资料、建议、负面结果或未决问题。大型原始数据留在实验平台；账本保存来源、绑定与必要制品。

| 关系 | 当前含义 |
| --- | --- |
| derived_from | 来源追溯；默认不把来源全文扩成结论依据 |
| depends_on | 必要前提；多个前提全部满足才成立 |
| refutes | 有效来源可推翻目标；来源也参与同一混合求解 |
| challenges | 相关争议入口；不单独自动排除目标 |

关系保存声明位置和精确端点绑定。同一 IM 账本内，资格从采用根沿必要前提、指向目标的反驳者及其相关闭包计算，不按关系声明在哪个 Issue 截断。不同账本仍隔离。必要绑定过期留下缺口，不能因失配边不再生效就把消费者当成有效。环保持确定的未决状态，不能任意选赢家。

当前结论的明确采用清单 R 不累积历史引用。B(R) 是必要闭包；正文只含有效根的闭包 S(R)。失败根及其原因进入短缺口摘要，通过冻结句柄按需展开；仍有效的前提不能冒充独立采用根。

D 出现只意味着可发现，明确冻结 D 并保存新结论才算采用。ABC 的资格恢复不覆盖后来结论。普通贡献、人工判定记录和旧类型关系不会替你改变当前 R。

已入账 Evidence 可在实际授权内直接拆分：原项和原有 packet/fact 映射保留，子项是独立身份，系统记录子项到原项的不可变拆分来源及当时的 Evidence 版本绑定。该来源既不证明原件已核验，也不隐含必要依赖。整理员可明确撤回或将原项的一条 scoped 关系替换为针对某个子项的关系，也可明确新增关系；未选择的关系保持原状。来源查询区分真实映射的当前和历史版本，不为子项伪造 fact。平台主体通过来源继承读取自己创建的子项，以其仍能读取原项为条件；独立授权仍按原有规则判断，不授予其他平台来源权。依据有实际变化时由现有 currentness 机制处理，无法完成影响解析时整次拆分回滚。

新现场使用 schema 10；旧拆分专用 ChangeSet 接口已退役。schema 9 及更早现场不迁移或自动接管，旧未决动作应保留原现场及请求/ChangeSet 标识，不能用新动作冒充恢复。新契约的未知响应沿原 journal 及请求身份恢复。具体工具与限制见 [IM 工具](../orchestration/IM_TOOLS.md)。

拆分并发检查固定原项直接关系以及 resolver 实际使用的有向依赖；无关多跳节点不可读不会自动禁止拆分，实际选择修改的关系仍逐项检查权限。整理员通过工具读到的关系版本会绑定后续选择，发生变化须重新查看和判断。来源查询保留可读项，并用不含身份的标记表示存在不可读子项。

规范与限制见 [统一语义](UNIFIED_MANAGEMENT_SEMANTICS.md)，工具操作见 [MCP](ISSUE_MANAGER_MCP.md)。
