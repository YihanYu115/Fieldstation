# Fieldstation 的设计理念

作者：Yi-Han Yu

科学研究可能持续很久，参与者、方向和已有结论都可能变化。Fieldstation 探索如何让人和 AI Agent 在有限的工作会话中留下可接续的贡献，而不依赖某一个参与者持续掌握整个项目。

## 设计要点

- **让研究记录支持接续。** Issue 组织研究问题；观察、分析、来源和未决问题可以逐步积累。Inbox 提供先保存材料、后整理的入口。
- **明确证据关系及其影响。** 参与者声明来源、必要依赖、反驳或争议；系统按明确规则计算证据资格，并帮助识别受变化影响的结论。人和 Agent 仍需判断关系是否成立及结论是否有科学依据。
- **让协作工具各自可用。** Queue 记录待办、领取和简短回复；Board 保存交流与请求。普通贡献不依赖固定岗位顺序，也不要求开启自动化。
- **将自动推进作为可选配置。** Listener 只读发现，可信 Python 脚本选择触发条件，Host 在配置和权限范围内处理会话启动。领取、启动和实际完成分别是不同的事实。
- **区分工作焦点和授权。** Issue 可以组织当前上下文，但不自行授予或缩减权限；参与者可在实际授权内向其他问题贡献。

## 状态与边界

Fieldstation 是早期研究原型。它提供的记录和计算机制不代替科学判断；长期科研效果、Agent 岗位表现、真实设备接入和生产部署仍有待验证。项目设计和具体实现的边界见[系统架构](WORKFLOW_ARCHITECTURE.md)、[Evidence 管理](EVIDENCE_MANAGEMENT.md)与[计算契约](UNIFIED_MANAGEMENT_SEMANTICS.md)。
